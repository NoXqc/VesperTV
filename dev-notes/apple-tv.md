# Apple TV (tvOS)

Plan (owner's Claude Doc "VesperTV on Apple TV — plan"): (3) test build with
the community engine, (4) libmpv player on tvOS, (5) TV layout, storage,
Siri Remote, (6) TestFlight, then the App Store on the same app record as
the iPhone app. Branch `claude/tvos-test` is step 3.

## Engine

Flutter has no tvOS. [flutter-tvos](https://github.com/fluttertv/flutter-tvos)
is a CLI + prebuilt Metal-only engine; each release pins one Flutter SDK
(`v3.47.9-tvos.1.11.5` = Flutter 3.47.9, the iPhone CI's version). macOS +
Xcode only, so everything runs on the GitHub Mac runner
(`.github/workflows/tvos-build.yml`). The CLI fetches its own Flutter.

- `flutter-tvos create --org com.nox .` in this project runs Flutter's own
  create (keeps existing files) and adds `tvos/` beside `ios/`: its own
  Info.plist, AppDelegate, Podfile / SwiftPM. Never share files with `ios/`.
- `tvos/` was generated by `flutter-tvos create` on CI (run 43666393531) and
  committed with three edits: bundle id `app.vespertv.player` (the iPhone
  app's, needed for one App Store record), display name VesperTV, and
  `NSAllowsArbitraryLoads` like `ios/`. Deployment target tvOS 15.0. Icons
  and Top Shelf images are still the template's.
- `wakelock_plus` 1.8+ declares `tvos:` but its tvOS code lives in `ios/`,
  which flutter-tvos never builds ("Module 'wakelock_plus' not found" in
  the registrant). The workflow strips that entry from the runner's pub
  cache so only `wakelock_plus_tvos` registers. Worth reporting upstream.
- Device builds must be signed with an **Apple Distribution** certificate:
  flutter-tvos signs its engine with it (ITMS-91065). Without it internal
  TestFlight works and external Beta App Review fails.
- Debug on a real Apple TV attaches over Wi-Fi (slow); the simulator is the
  fast path. Release / profile need no debugger.

## Dart side

- On tvOS `Platform.isIOS` is **true** (and `defaultTargetPlatform` is iOS);
  `Platform.operatingSystem` is `'tvos'`. `isAppleTv`
  (`utils/desktop_platform.dart`) reads `operatingSystem`, because the
  engine's own `Platform.isTvOS` doesn't exist in the stock SDK we analyse
  with. iPhone-only flags exclude it: `usesMediaKit`, `usesMediaKitTarget`,
  `isIosTarget`, `needsBackArrow`, `IosPip.available`, voice input.
- `appStoreBuild` stays true on Apple TV (same App Store rules).
- `DeviceTypeService.isTelevision()` answers true on Apple TV (no Kotlin
  channel), so the app takes the Android TV layout.
- Player: media_kit (the computers' / iPhone's `DesktopPlayerScreen`
  stack, non-touch layout) once libmpv loaded at startup
  (`appleTvMediaKitReady`, main.dart). If it didn't, the Android stack's
  Dart side (`video_player_hdr` -> `VideoPlayerPlatform`) with
  `video_player_tvos` (Apple's player: HLS and MP4, not raw .ts or MKV).
- A tvOS build loads only plugins with a `tvos:` entry; any other plugin
  throws `MissingPluginException` when called (the app's Kotlin channels,
  media_kit, flutter_inappwebview, file_selector). Ports in pubspec.yaml:
  shared_preferences, path_provider, sqflite, wakelock_plus,
  package_info_plus, url_launcher, video_player (`*_tvos`, fluttertv.dev).
  They declare only `tvos:`, so other platforms never load them.
- Siri Remote: swipes = arrow keys (held = repeat ~80 ms), click = Enter,
  Menu = `popRoute` (Back), Play/Pause = mediaPlayPause. A click near the
  clickpad's edge becomes an arrow (flutter-tvos `dpadDeadZone` 0.5).
- **Hold OK (2026-11-21, Mycue66 on Discord: Sports Mode's hold OK for stats did
  nothing):** flutter-tvos auto-repeats held arrows only (its native
  `keyRepeatInitialDelay` / `keyRepeatInterval` 400 / 80 ms are "on a held
  arrow/page button", `packages/flutter_tvos/lib/src/rcu/tv_remote_controller.dart`
  at v3.47.9-tvos.1.11.5); a held click sends key-down ... key-up and nothing
  between. Every hold in the app needs repeats (`HoldToActivate`, the Sports
  Mode feed, the live panel, the player side panel, Multiview...), so no hold
  ever opened on Apple TV. `services/held_ok_repeat.dart` (`HeldOkRepeat`,
  installed in main.dart on Apple TV only) sends Android's repeats while an
  activate key is down: first at 500 ms, then every 50 ms, through
  `HardwareKeyboard` + the focus tree, until the key-up; a tick that comes
  late sends nothing (a queued key-up wins); a key the platform repeats
  itself is left alone. `test/held_ok_repeat_test.dart`. Not tried on a box.
- Menu on the top screen must leave to the Apple TV Home screen (App
  Review). The engine makes every Menu press Back, so `VesperViewController`
  (tvos/Runner/AppDelegate.swift, set in Main.storyboard) lets a Menu press
  go up the responder chain (the system then leaves the app) when Dart said
  so ahead over `vespertv/tvos` (`services/apple_tv_menu.dart`): the TV home
  reports after each build whether Back would exit (tabs column, nothing
  above, no profile selector; `_reportAppleTvRoot`), any route push clears
  it (`AppleTvMenu.observer`), and Back reaching a top screen anyway
  (Sports Mode, Who's watching) arms the next Menu press for 10 s with a
  hint (`AppExit.warm`). Not tried on a box yet: if `next?.pressesBegan`
  doesn't leave, the fallback is the arm path only.

## Player (libmpv)

- `tools/tvos/build_mpv_framework.sh` (tvOS workflow, cached by the
  script's hash): MPVKit 1.0.0's LGPL static tvOS libraries (libmpv, FFmpeg
  8/9, libass, dav1d, libplacebo, MoltenVK, gnutls/openssl...) linked into
  one dynamic `Mpv.framework` per slice (device arm64, simulator arm64),
  `-force_load` libmpv, only `mpv_*` exported (54), ~32 MB each, as
  `Mpv.xcframework`. media-kit's own libmpv builds have no tvOS.
- `third_party/media_kit_video_tvos`: media_kit_video 1.3.1's iOS plugin
  code unchanged (libmpv -> OpenGL ES -> CVPixelBuffer -> Flutter texture;
  software rendering on the simulator) with a tvOS podspec vendoring the
  framework and linking it into the pod itself (`OTHER_LDFLAGS`).
- media_kit picks libmpv by `Platform.operatingSystem` (no `'tvos'`): the
  Runner sets `LIBMPV_LIBRARY_PATH=Mpv.framework/Mpv` before the Dart VM
  starts (AppDelegate `init`), which every lookup reads first;
  `MediaKit.ensureInitialized(libmpv:)` gets it too.
- CI smoke test `lib/tvos_player_smoke.dart` (`-t`, run by
  `tools/tvos/sim_run.sh smoke`): HLS, raw .ts and MKV samples 25 s each,
  player state + mpv warnings every 2 s, screenshots.
- MPVKit calls itself "only suitable for learning": pinned to 1.0.0.
  Fallback if it fails on a box: AetherEngine (LGPL, FFmpeg +
  VideoToolbox, no libass).
- Still to check on a real Apple TV: the OpenGL ES (hardware) path,
  VideoToolbox decode, 4K HDR, memory. `newDesktopPlayer(bigCache:)` keeps
  Apple TV at media_kit's 32 MiB cache like iPhone.

## Remote in the player and Multiview (+915)

First box report (Discord, roman, TestFlight 902, 2026-11-20): the
full-screen bar was on screen from the start while the picture held the
remote, so every arrow zapped (Up / Down) or opened the side panel (Left);
OK put focus on Play / Pause but the focus tint was a faint grey circle;
the bar had no Multiview; in Multiview the "+" did nothing (the screen-size
key wrapper was the only focus stop: no arrow found a screen, OK did
nothing); closed captions were on with no button to turn them off on live.
`DesktopPlayerScreen` and `DesktopMultiviewScreen` now ask
`AppPreferences.isTelevision` (true on Apple TV, false on computers and
iPhone, so those keep their mouse layout):

- Player: the bar shows the channel 3 s at open, then hides. OK = bar with
  Play / Pause focused (movies too; Up / Down on a movie as well); the bar
  hides 6 s after the last key unless paused or a menu from it is open
  (`_armTvBarIdle`). Movies / catch-up: Left / Right on the picture = 10 s
  back / ahead (Right = sources when there are some). A ring in the
  theme's colour on the
  focused button (Icon / TextButton theme around the bar, all non-touch).
  No top-left Back (Menu does it) and the side tab isn't a focus stop on a
  TV; no volume slider (the TV's remote; it also kept Left / Right).
- Bar: **Multiview** (live, not catch-up, computers too) = this player
  stops its stream (one connection per screen), Multiview opens with the
  channel on screen 1, Back plays the screen with the sound here again
  (`DesktopMultiviewScreen.initialChannel`, pop result). **Subtitles** on
  live too (CC on / off), iPhone included.
- Multiview: each screen is a focus stop (white frame on a TV), the first
  has focus. OK: empty = picker, playing = sound, the one with the sound =
  Change channel / Reload / Remove / Swap mode. Hover buttons excluded from
  focus on a TV. Picker: search field behind `TvTextFieldGate`, the first
  channel focused (computers still type at once).
- The player's screen-size key node (`_rootFocus`) is `skipTraversal`:
  as a traversal stop its centre was nearer than the next button, so Left
  from Stop landed on it instead of Multiview (CI tour of +915, fixed in
  +919; 915 on TestFlight has it).
- CC: mpv's captions track is switched off also when the track list
  arrives after the selection (`configureDesktopStreamPlayer`).

`test/desktop_multiview_remote_test.dart`. The player has no widget test
(media_kit needs libmpv); the CI tour walks bar -> Multiview button ->
Multiview -> picker -> back (`lib/services/ci_tour.dart`).

## Siri Remote touch surface (TestFlight 954)

itSoTek (Apple TV 4K 3rd gen) and Mycue66: the lightest touch moved the
selection. The flutter-tvos engine turns touchpad swipes into arrow keys
itself (stock: one arrow per 0.3 of the pad, auto-repeat after 3 small
moves). `services/apple_tv_remote.dart` sends calmer values through the
`flutter_tvos` package (`TvRemoteController.config` + `init()`, applied in
main.dart before runApp; a no-op off tvOS): Normal (default) 0.5 / repeat
after 6 moves, Less sensitive 0.65 / 8, Very sensitive = the engine's own.
Settings > Backup & devices > Remote > Touch surface, Apple TV only,
`vesper_tvos_touch`, this device only. Not tried on hardware before 954.

## Storage (done on the branch)

A physical Apple TV lets apps write only to Caches and tmp (Documents is
read-only; the simulator allows it, so only a box shows it), NSUserDefaults
is meant for ~500 KB, and tvOS may empty Caches when space runs low while
the app isn't running. `services/apple_tv_storage.dart`, installed by
`AppLog.capture(setup:)` before the log file opens (Apple TV only):

- `AppleTvPaths`: path_provider's Documents -> `Caches/Documents`,
  Application Support -> `Caches/Support`. Every caller and plugin (catalog
  DB, guide DB, Media Hub cache, backups, recordings.json, photos,
  wallpapers, log) follows without changes. sqflite_tvos already keeps its
  default databases path in Caches.
- `AppleTvPrefsStore`: SharedPreferences in `Caches/Support/vesper_prefs.json`
  (no size limit), plus a copy in NSUserDefaults
  (`flutter.vesper_appletv_prefs_copy`) while the JSON is under 400 KB. The
  file wins; the copy restores settings and logins when Caches was emptied.
  Over 400 KB the copy is removed (cloud sync is then the way back).
  `test/apple_tv_storage_test.dart`.

## TestFlight (prepared, not run yet)

Run "tvOS build" by hand with **testflight** ticked (Actions tab): a release
build staged right before a signed `xcodebuild archive`, exported with
`tvos/ExportOptions.plist` (upload), through the same four secrets as the
iPhone job. Before the first run:

1. App Store Connect > VesperTV > add the **tvOS** platform (same bundle id
   `app.vespertv.player`, one listing for iPhone, iPad and Apple TV).
2. Bump `+N` in pubspec.yaml if this version's Apple TV train has seen it.
3. flutter-tvos signs its engine with an Apple Distribution certificate
   from a keychain; without one only internal TestFlight works (external
   testers and App Review reject an unsigned engine, ITMS-91065). Since
   2026-11-20 the upload step imports it from two secrets into a temporary
   keychain: `APPLE_DIST_CERT_P12` (the .p12, base64) and
   `APPLE_DIST_CERT_PASSWORD`. Made without a Mac: openssl key + CSR on the
   owner's PC (outside the repo), certificate from developer.apple.com, .p12
   in the 3DES / SHA-1 format the macOS keychain reads. Valid until
   2027-11; renew it the same way. The step warns in the log when the
   engine still went unsigned.
