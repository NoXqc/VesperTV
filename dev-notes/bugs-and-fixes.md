# Known bugs & their fixes (history — don't regress these)

Check this before investigating a bug: it may already have been root-caused. Section references (§6.4, §10 …) point to `release.md` and `CLAUDE.md`.

## 11. Known bugs & their fixes (history — don't regress these)
| Symptom | Cause | Fix / where |
|---|---|---|
| What's New: playing a title showed "Select a channel to start watching" | the TMDB-curated id list wasn't filtered by enabled playlists; `play()` refused a disabled playlist's title and the pane hid the error | curated lists check `isPlaylistEnabled`; the pane shows `playback.error`; a curated list that matches nothing is rebuilt once per session (1.0.18) |
| Search: picking a recent search reopened the keyboard and trapped the remote | the focused chip left the tree with the results; focus fell back to the search field | `_resultsHolder` takes focus, then the first result row (1.0.18) |
| Settings > Add-ons switch wouldn't turn on | first run's list is `AddonService`'s const default list; writing into it threw | toggle works on a copy (1.0.18) |
| Audio track button missing on a multi-language movie | track list read once when the controls first built, before the file header | retries every 3 s up to 5 times (1.0.18) |
| First quick OK on a hold row (TV Favourites, Fire Stick) opened its hold action ("Clear favourites?") | busy box: the click's key-up reached the app later than the 550 ms hold timer | `HoldToActivate` fires a hold only after a key **repeat** (real holds always repeat; a late key-up never does) (1.0.17) |
| Starring ESPN 4K also put ESPN HD/FHD in Favourites (hide/Sports picks the same) | Live channel id = provider EPG id (`epg_channel_id`/`tvg-id`), shared by every copy of a channel | `Channel.withUniqueIds` on every live load (`playlist_session.dart`): shared ids become `<epg id>#<stream id>`, EPG id kept in `Channel.epgKey` (1.0.16). Saved state on those channels reset once |
| Add Playlist: Back to close the keyboard on the **Name** field jumped to fullscreen live; Back again returned | `LiveResumeHint`'s global hold-Right (1200 ms) timer was armed while a text field had focus, and the Fire/remote keyboard sequence fired it | `LiveResumeHint._textFieldFocused` gates both arming **and** `_resume()` (`live_resume_hint.dart`) |
| Cold launch opened the first live group instead of Favourites | `_effectiveLiveGroup` used only `currentChannel`, which is null on cold launch | favourites-first using `currentChannel ?? pendingResumeChannel` (`tv_home_screen.dart`) |
| Add Playlist: Right from fields never reached the Add button; up/down escapes buggy | focus escape logic per field | explicit `_modeScope/_fieldsScope/_statusScope`, `_handleFieldEscapeKey` with a unified field list; mode rows use `TvMenuTile(focusNode:)` |
| Multiview: main stream/audio kept playing after "Open in Multiview" | player not stopped | `await _playback.stop()` before push |
| Multiview: in-place audio toggle stalled / no audio | see §10 | reverted to recreate-via-`_assign` |
| Windows: "can't go truly full screen" (title bar + taskbar, ~98%) | native runner only shows a bordered window | `window_manager` always-fullscreen launch |
| Windows: Minimize did nothing / Close did nothing / Alt+Tab-away fine | minimize blocked in fullscreen; `SystemNavigator.pop` no-op | see §10 Windows |
| Windows: hold-to-menu only worked with keyboard Enter | no pointer long-press | `RawGestureDetector` in `HoldToActivate` |
| Windows: last channel not resumed at launch | nothing recorded it | `DesktopPlayerScreen` records `setLastChannelId`; `_autoResumeLastChannel` pushes it |
| Windows build `LNK1104` | exe still running | kill `VesperTV` first |
| Rebranded APK still purple (default theme) | Platinum's accent pair + splash were hardcoded purple/magenta | gold values in `constants.dart` and `main.dart` splash |
| Fire TV home tile still shows the old purple "N" after updating (phones show the gold V) | Fire OS keeps the launcher icon captured at first install | **not fixable in-app**; renaming the icon resources (3.53.1) did not help; only uninstall + reinstall refreshes it |
| Updater never offers a lower-numbered release (1.0.0 < 3.x) | strict "newer" compare | `_isDifferent` (§6.7) |
| `gh release edit --notes` referenced "notes below" and wiped them | `--notes` replaces body | write self-contained notes with `--notes-file` |
| Release asset update didn't change what `/latest` serves | tag left on old commit | repoint tag to HEAD (§6.4) |
| Formuler adb "device not found" | its IP changed | reconnect on `192.168.1.46:5555` / check its Settings > Network |
| EPG not ready for ~50 s after launch on the Formuler (measured: load began 26.5 s, decode took 24.8 s for 167k programmes; refresh = parse 26.9 s + save 20.3 s, the save being the Fire Stick OOM) | `EpgService.init` decoded one big JSON cache of every programme into memory; refresh rewrote it whole | **Fixed (+190):** SQLite `EpgDatabase` (`vesper_epg.db`), rows written in 1000-row batches while parsing; startup preloads only now/next (~4 h) for all channels, Timeline rows load on demand. Now ready **0.5 s after launch** (during the splash). Window 2 h back / 36 h ahead; refresh every 12 h (options 6/12/24). Windows not yet verified. `startupTiming`/`refreshTiming` lines in EPG Settings are TEMPORARY — remove after Windows + Fire Stick checks |
| A playlist's groups show no EPG at all (e.g. OTT "AM USA CBS/NBC/FOX/ABC" locals) | provider's XMLTV has zero programmes for those ids (verified on the VPS: 0/239, 0/257, 0/231) | not an app bug — needs a third-party US-locals feed (custom EPG URL, or a 2nd `epg` source on the Tuliprox input) |
| "Update EPG Now" → `TimeoutException after 0:00:30` | request never reached the VPS (no nginx log line; the box's own successful fetches take 2-5 s) | box-side network/VPN blip — retry; raising the timeout wouldn't help |
| Multiview tiles freeze/stall every ~40-60 s (both tiles, staggered); old fix "recreate both players on every audio swap" | two tiles on one provider account that allows only **1** connection: the provider kicks one, Tuliprox reconnects and splices into the same socket (TS sync lost, PTS jumps back 15-26 s) → AudioSink `UnexpectedDiscontinuityException` → clock freezes | not fixable in-app; one tile per account or a 2+-connection provider runs clean (25+ min, Fire Stick). Popup on entering Multiview explains it. Audio swap is now volume-only (+191) |
| Multiview tile: picture freezes, audio continues, then BUFFERING/READY flapping every second | Fire Stick MTK hardware decoder stops; undecoded video fills the load budget, audio starves | frozen-video watchdog in `ExoPlayerEventListener` (texture players) reconnects the tile in ~2-3 s; decoder errors (`ERROR_CODE_DECODING_FAILED`) also auto-recover |
| Multiview 720p tiles show the picture top-left with the rest solid green (fullscreen fine) | Flutter's ImageReader texture producer ignores the decoder's crop rect; MTK hands 720p frames in a 1920x1080 buffer | `VideoPlayerPlugin.createForTextureView` forces the SurfaceTexture producer (`debugForceSurfaceProducerGlTextures`). Sizing the producer (`setSize`) and capping codec max size did **not** help |
| Multiview tile solid green for a true 4K channel (ESPN 4K = HEVC 3840x2160 HDR10, colour transfer 6/PQ) on the **Formuler only**; fullscreen fine | Formuler (Amlogic) decoder can't output 10-bit HDR into the SurfaceTexture Multiview tiles use (fullscreen uses a SurfaceView) | **Won't fix (owner, 2026-10-17):** works in a tile on the phone (Qualcomm `c2.qti.hevc.decoder`) and Fire Stick (`HW.omx.video.hevc`, real 3840x2160 at ~20 Mbps, 1080p monitor irrelevant). If more boxes show it: in a tile, swap to the channel's FHD copy or show "4K plays in full screen only" |
| Fire Stick went to screensaver during Multiview | Multiview never took a wakelock (and "Open in Multiview" stops the player, releasing its one) | `WakelockPlus.enable()` for the Multiview screen's lifetime |
